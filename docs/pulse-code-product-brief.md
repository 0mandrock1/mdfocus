# PULSE CODE · TypeScript як конструктор, а не зменшена IDE

**Версія концепту:** v3 · 21 листопада 2026.
**Прототип:** https://tools.mandrock.me/mdfocus/pulse-code-demo.html
**Галерея:** https://tools.mandrock.me/mdfocus/?url=https%3A%2F%2Ftools.mandrock.me%2Fmdfocus%2Fdemo-images.md
**Принцип:** людина не приходить із гарантовано завершуваною мікрозадачею. Вона має код, контекст і хвилину чи пів години. Застосунок повинен дозволяти просуватися по кроках, не вдаючи, що невелика задача вже сформульована.

## 0. Що прибрано з v2

- Немає автоматично вигаданої «90-секундної задачі» чи таймера. На вході: **продовжити контекст / вибрати фрагмент / почати чистий експеримент**.
- Чотири сектори **не вважаються повним словником програмування**. Вони лише перший вузол навігації.
- Колесо не слід перевантажувати більше ніж чотирма секторами: в Touchviz підтверджена нижня межа цілі 44px, радіальна глибина 52px для R1=60, R2=112.
- Одна дія не примушує закривати сесію. Можна застосувати скільки завгодно послідовних виборів, змінити окремий слот і використати Undo.
- Рендери не слід сприймати як готову TS IDE: UX-прототип демонструє механіку введення, а не реальний language server.

## 1. Ввід у стилі поступових вправ, не копіювання Duolingo

Послідовний, **низько-когнітивний крок**: один намір → один розділ → конкретний фрагмент → попередній перегляд → застосувати до локальної чернетки. Результат видно одразу. Кожен крок можна повернути назад.

Немає «правильного варіанту» або score; це **не навчальна вікторина**. Користувач збирає довільний власний TypeScript-код. Великими картками замінено пошук символу на маленькій клавіатурі. Потрібен повний свобідний текст? Є окремий режим текстового введення.

Відкриття реального репозиторію, автодоповнення типів і перелік доступних символів згодом мусять походити з `tsserver`, але це окремий етап. Нинішня таблиця наповнена **статичним TS-словником для демо**.

## 2. Інформаційна геометрія

`1/2` **радіальне меню «що редагую?»**: Структура · Значення · Типи · Дії.

`2/2` **радіальне меню «яка родина?»**:
- Структура → Оголошення / Умови / Потік / Функції
- Значення → Символи / Літерали / Виклики / Оператори
- Типи → Базові / Колекції / Utility / Контракти
- Дії → Навігація / Історія / Рефакторинг / Перевірка

Фінал: **повноекранна таблиця**, а не третє мікрокільце. На 320px — дві широкі колонки, ≥560px — три; висота плитки ≥92px на короткому екрані, ≥101px на звичайному. У таблиці є пошук, видима ієрархія, скрол, попередній перегляд вибраного фрагмента і великий нижній CTA «Додати до чернетки».

У словнику демо **159 варіантів**: 40 для Структури, 48 для Значень, 48 для Типів, 23 для Дій. Це не обіцянка повноти TypeScript, а доказ, що обсяг не обмежений фізичною кількістю секторів.

## 3. Фізика Modwheel

Основа в Touchviz: `/root/projects/tools/touchviz/docs/design/modwheel-unified-2026-09-03.md`, `src/ui/wheel.js`, `src/ui/wheel-view.js`. Перевикористані принципи геометрії/станів, не копія коду.

- **Звичайний тап** на великому хабі відкриває повністю функціональний вертикальний список із великими рядками, VoiceOver/keyboard fallback. Жест не обов'язковий.
- **Утримання 340 мс** відкриває колесо, рух ≥16px теж може відкрити його без очікування.
- **Відпускання на секторі першого рівня** залишає вибраний розділ, другий жест обирає підгрупу. **Утримання над сектором 260 мс** може перейти до другої глибини в рамках одного безперервного жесту.
- Після автоматичного занурення потрібен **новий рух ≥24px**, аби випадково не обрати сектор другого рівня простим відпусканням.
- `pointercancel` скасовує жест; `pointerup` звіряє реальний elapsed time, якщо timer запізнився. Центральна зона й вихід поза кільце не вставляють код.
- Фіксований радіус, а не масштабована мішень: `R1=60, R2=112`, чотири сектори 90°, вписана мішень діаметром 52px; центр обмежено safe-region viewport. Ліворуч/праворуч можна дзеркалити хаб.
- Другий рівень має ті самі 4 сектори, але іншу таксономію; breadcrumb `1/2`/`2/2` пояснює зміни контексту. Back повертає на рівень вище.

## 4. TypeScript input як композиція, не вставка випадкових символів

Конструктор тримає **окремі замінні слоти**: `structure`, `value`, `type` плюс ручний TS-текст. Новий вибір у слоті замінює саме цей слот, а не дублює старий шматок у нескінченний список. Історія — до 30 попередніх станів.

Демонстраційний фрагмент: `calculateLoss(s: Score)`. Структура/вираз/тип виводяться в контексті функції. Код та checkpoint відновлюються з `localStorage` після перезавантаження. Для реального застосунку потрібні `IndexedDB`, стабільні symbol IDs від TS LS, відновлення editor selection, багатодокументні стани та конфліктні ревізії.

**Важливе обмеження:** нинішній конструктор робить **текстову, не AST-типобезпечну композицію**. Деякі варіанти можуть бути несумісними за типами, і typecheck не запускається. Це показано як UX-демо, без удаваного `tsserver` чи зелених тестів. Тільки після реального LS можна вводити dependency-aware підказки та відкидати невалідні комбінації.

## 5. Мікросесія без мікрозадачі

1. Відкрив на 30 секунд → є збережений workspace/документ/точка входу, без обов'язкового завдання.
2. Обрав щось у колесі → конкретизував у таблиці, побачив результат локально. Можна зупинитися до вставлення.
3. Якщо сесію обірвало iOS, локальний стан і вибір не втрачаються за звичайного reload. Перевірка примусового kill на реальному iPhone ще потрібна.
4. Повернувся → одразу той самий чернетковий контекст. Відсутність мережі не повинна імітувати синхронізацію.
5. Diff/checkpoint — **не обов'язковий фініш**; можна повернутись до редактора або відкласти. Реальний save/commit/push — окремі явні операції.

## 6. Ризики та вимоги MVP

| Failure mode | Кращий контракт |
|---|---|
| Дрібні touch targets | ≥52px сектор, ≥49px кнопки, великий fallback-список |
| Палець стоїть на секторі під час зміни рівня | Не застосовувати сусідню підгрупу без нового переміщення |
| Потрібно 200+ TS-понять | Рівні + повноекранна пошукова таблиця, а не 200 секторів |
| Немає TypeScript symbol у поточному scope | LS-backed меню: приховати/позначити недоступне з поясненням; не підставляти вигаданий id |
| Неточний вибір літерала | Preview, підтвердження застосування, Undo |
| iOS сховав застосунок | Durable локальна чернетка перед відходом; відновлення без втрати |
| Паралельна правка з VPS/іншої вкладки | Revision check, conflict diff, жодного last-write-wins |
| Довга затримка кадру | Elapsed-time fallback на `pointerup`, скасування через `pointercancel` |
| Помилковий зелений стан | Ніколи не називати TypeScript валідним без реального typecheck на відповідній ревізії |
| Довільний каталог на VPS | Workspace allowlist; canonical paths, symlink escape check, auth gate |
| Реальний `Save` після обриву мережі | Ідемпотентний server operation, reread confirmation, ніякого сліпого повтору |

## 7. Definition of Done наступного, справжнього MVP

На реальному iPhone: відкрити файл, вибрати TS-вузол, зібрати валідний фрагмент зі справжнього семантичного словника `tsserver`, зберегти в локальний draft, переглянути diff, записати на сервер з version check, підтвердити байти на VPS. Повторити на 320×568, 390×844, із системною клавіатурою, лівою рукою, при зірваному жесті, перерваному з'єднанні та зовнішньому редагуванні файла.

Прототип v3 демонструє тільки UI-конструктор, локальне застосування та повернення до контексту. Реального серверного запису, повноцінної AST-редактури, LSP/typecheck і Git-операцій немає.
