# PULSE CODE · TypeScript у коротких мобільних сесіях

**Статус:** продуктова чернетка v2, 21 листопада 2026 року.  
**Мета:** працювати з TypeScript на VPS, коли є 1–3 хвилини й одна рука.  
**Форма:** iPhone-first PWA. Не зменшена десктопна IDE.  
**Артефакт для перевірки жесту:** [живий UX-прототип](https://tools.mandrock.me/mdfocus/pulse-code-demo.html). Він **не змінює серверні файли**.  
**Три статичні концепти:** [MDfocus-галерея](https://tools.mandrock.me/mdfocus/?url=https%3A%2F%2Ftools.mandrock.me%2Fmdfocus%2Fdemo-images.md).

## Вхідний сценарій: «Я маю півтори хвилини»

Не треба обирати репозиторій, шукати теку чи згадувати, де стояв курсор. Застосунок відкриває *конкретну останню незавершену дію*: «Виправити nullability у `calculateLoss()`, `luna-review.ts`; останній фрагмент; одна зміна». Якщо задача не відновлюється однозначно, показує максимум дві recent-картки, **не вигадує роботу**. Кнопка **«Продовжити»** одразу повертає до місця й стану. Кнопка **«Відкласти»** закриває сеанс без втрати локальної чернетки.

«90 секунд» тут UX-орієнтир, а не таймер, який змусить вийти посеред редагування. Телефон може бути мокрим, рука зайнята, людина може розблокувати його тричі за хвилину. Застосунок має терпляче витримувати переривання.

![Мікросесія PULSE CODE: одна TS-задача, великі кнопки, повернення до контексту](https://tools.mandrock.me/mdfocus/pulse-session.svg)

## Проблема, яку звичайний редактор не розв'язує

На екрані 320–390 px пальцем важко попасти в 12-піксельну позначку, перемістити курсор до третьої дужки, закрити маленький таб і точно потрапити в hunk. Тому редагувати *символи* не може бути єдиним режимом. Перший пріоритет: **дія над TypeScript-сутністю**, а точне введення тексту тільки коли воно справді потрібне.

**Заборонені UI-рішення для MVP:** постійне файлове дерево, 4–5 дрібних табів, одразу відкрита клавіатура, три ряди кнопок, міні-термінал на старті, Git-хром із десятком іконок, авто-push, блокуюче AI-вікно. Вони крадуть екран та увагу.

## Основна механіка: TypeScript Modwheel

![PULSE CODE: кодова сутність та кільце TypeScript-дій з великими секторами](https://tools.mandrock.me/mdfocus/pulse-wheel.svg)

**Виклик:** великий круглий майданчик у досяжній зоні великого пальця, за умовчанням праворуч, із перемиканням на ліву руку. Не довге натискання *на тексті*, яке конфліктує з нативним selection Safari. Утримати ~340 мс → колесо, провести по сектору → відпустити → застосувати; рух понад 16 px може відкрити його негайно. **Звичайний тап** відкриває еквівалентний вертикальний список із великими рядками. Для VoiceOver та клавіатури колесо не є обов'язковим.

**Чотири дії рівня 1:** Rename symbol, TypeScript Fix, Go to definition, Organize imports. Це не список довільних shell-команд. Словник дій залежить від поточного вузла TypeScript і фактично доступних code actions; недоступні дії не можна маскувати під робочі.

**Геометрія:** модель заснована на Touchviz `modwheel`, але не пряме копіювання його коду: внутрішній радіус 60 px, зовнішній 112 px, чотири сектори по 90°. Найбільше вписане коло сектора має діаметр **52 px**. Центр притискається до безпечної зони [124, width−124], а не масштабується разом із шириною екрана. У центрі й поза зовнішнім кільцем відпускання скасовує вибір. Відповідний сектор підсвічується до відпускання; важливі дії можуть вимагати окремого підтвердження. Тактильний відгук тільки там, де API доступний, без залежності логіки від нього.

**Арбітраж жестів:** `pointercancel` нічого не змінює. Коли event loop затримав таймер, `pointerup` перевіряє фактичний elapsed time; long-press не зникає мовчки (виявлений failure mode старого Touchviz). Wheel не перехоплює звичайний скрол кодового полотна та selection тексту. Коли відкрилася системна клавіатура, колесо перепозиціюється або переходить у bottom sheet, а не вилітає за viewport.

**Нестандартне продовження після MVP:** semantic scrub: після вибору `function` рух угору/вниз циклічно переходить між sibling-вузлами AST, ліворуч/праворуч міняє рівень `argument → call → statement → block`. Прев'ю виділення видно *до* підтвердження, коди не редагуються при переміщенні. Це інструмент для неточних тапів, а не заміна touch selection.

## TypeScript не «ще одна мова»

Перший реліз проєктується навколо **TypeScript language service (`tsserver`)** біля коду на VPS: symbol graph, definition/references, diagnostics, rename, code actions, organize imports, типізований контекст. Фронтенд використовує **CodeMirror 6** як текстове поле, але найкоротший користувацький шлях іде через семантичні дії. `tsserver` працює у workspace із явною `tsconfig`, без довільного виконання чужих команд із проєкту. Діагностика має відображати конкретний файл, версію і момент останнього аналізу.

Python, PHP, Markdown та інші формати можуть відкриватися **як звичайний текст** після MVP, без обіцянки такого самого семантичного UX. Плагіни інших мов не є критерієм першого релізу.

## Останній екран: одна зміна, один наслідок

![PULSE CODE: одна зміна, вертикальний diff, велика дія збереження та пауза](https://tools.mandrock.me/mdfocus/pulse-review.svg)

Не side-by-side diff і не повноцінний Git dashboard. Показати **лише hunk поточної мікрозадачі**: до / після, назва файла, точний статус «Локальна чернетка» чи «Записано на VPS». Велика кнопка **«Зберегти на VPS»** після перевірки серверної ревізії. Друга велика кнопка **«Відкласти без втрати»**. Git commit/push/deploy відсутні в цьому флоу, вони окремі навмисні операції.

При конфлікті не питати «перезаписати?»: показати 3 контексти (твій diff, нова серверна ревізія, результат merge) і зберегти локальну версію. Мережа пропала після запиту? Не робити сліпий повтор: за `idempotency_key` перевірити, чи сервер застосував зміну.

## Екранна ергономіка й короткі сеанси

| Ситуація | Правило |
|---|---|
| Палець промахнувся на 15 px | Запас для 52px сектора, великі дії ≥56 px, fallback-список |
| Змінив руку | Дзеркальний dock колеса, без перебудови м'язової пам'яті всього екрана |
| Дрібний текст TS | Ні одного кроку, що *вимагає* текстового курсора; zoom не ламає екран |
| Телефон повернули в кишеню | Локальна чернетка та caret/AST-позиція зберігаються негайно, відновлення після kill |
| Сеанс триває 30 секунд | Одним натиском зупинити; немає mandatory save-dialog |
| Немає мережі | Показувати «Локально» і заборонити обманливий «Синхронізовано» |
| 320×568 або клавіатура на половину екрана | Колесо та action-sheet у доступній зоні, одна головна дія, без горизонтального переповнення |
| Незрячий користувач або неточний жест | Усі команди дублюються списком, озвучуються VoiceOver і доступні з клавіатури |

## MVP-контракт

1. **Resume:** сесійний journal з `workspace_id`, `file_revision`, `symbol_id`, дією та локальним draft; відновлення контексту одним тапом. `localStorage` лише у демо, в продукті потрібні IndexedDB та облік quota/eviction.
2. **TypeScript-aware actions:** віддалений `tsserver` для діагностики, rename та code actions, із таймаутом і скасуванням; при деградації LSP працює safe text mode без удаваного TS-fix.
3. **Modwheel:** geometry floor, лівий/правий режими, haptic optional, tap fallback; тест різних орієнтацій, `pointercancel`, довгих затримок main thread і системної клавіатури.
4. **Safe edit:** `draft → diff → optimistic version check → atomic write → reread/ack`; попередження при зовнішніх змінах. Жодного збереження в мережу з одного лише autosave локальної чернетки.
5. **Діагностичні події:** `session_resume`, `wheel_open`, `wheel_cancel`, `wheel_action`, `draft_saved`, `remote_conflict`, `remote_ack`, `tsserver_latency`, без коду, приватних шляхів чи секретів у логах.
6. **Відкладено:** повноцінна IDE, multi-language LSP, Git UI, виконання скриптів, термінал, авто-деплой і AI-chat. Це не повсякденний шлях «на 90 секунд».

## Приймання, яке можна перевірити

На реальному iPhone з екраном 390 px і симульованим 320 px провести повний флоу: відновити TS-задачу → вибрати вузол → викликати колесо → застосувати code action → побачити diff → зберегти або відкласти. Повторити лівою рукою, мокрим/неточним пальцем, після вивантаження PWA, без інтернету, під час зміни файла другою сесією. Окремо зафіксувати частку промахів по секторах, медіану часу до першої корисної дії та відсоток втрачених чернеток. **Цілі**: не більш як один стартовий тап; ≥52px wheel sectors; нуль випадкових серверних записів; нуль втрачених локальних змін у цих тестах. Це критерії, **не виміряні результати**.
